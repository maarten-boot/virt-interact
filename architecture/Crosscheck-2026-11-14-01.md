## 2. Code checked against the Spec and Plan

| # | Finding | Severity | Proposed fix |
|---|---------|----------|--------------|
| C1 | **A stale SSH connection can come back after "forget".** `Worker::forget` (host edited), `forget_all` (config reloaded) and host removal clear the session map. But a refresh that is still connecting inserts its new session when it finishes. After an edit (e.g. a new port or user) during a refresh, the next refresh silently reuses the connection made with the *old* settings. For a removed host, the session stays open until the app exits. SPEC-006 (as reworded in phase 4) says the connection is dropped when the host is edited or removed. | Medium | Keep a generation number per host. `forget` increments it; a finishing task stores its session only if the generation is unchanged. Test: start a slow connect, forget, let it finish, refresh again; expect a second connect. |
| C2 | **Disabled buttons look like enabled ones.** With `disabled_alpha = 1.0` (needed for contrast), egui draws a disabled button exactly like an enabled one, minus the hover effect. "Refresh selected" with nothing selected, and "Refresh" while a host is busy, look clickable. SPEC-001 says disabled widgets use the palette's disabled text colour; that colour (`theme::disabled_text`) is not used anywhere. | Medium | A helper `button(ui, enabled, text)` that draws the label in the disabled colour when disabled (that colour meets the minimum ratio), used for every button that can be disabled. Test: a headless frame where the disabled button's text colour is the palette's `disabled_text`. Alternatively, hide disabled buttons, but that is worse for discoverability. |
| C3 | **A passphrase typed and then skipped is not wiped.** On "Skip this key" (or Enter with an empty field), the `String` buffer is dropped without zeroing. Only the OK path wraps it in `Secret`, which zeroes on drop. SPEC-006 says passphrases are wiped after use. | Low | Always move the buffer into a `Secret`, and drop it on skip. |
| C4 | **Status ages go stale.** "ok, 5 min ago" and the inventory age only update when egui repaints, which happens on input. An idle window keeps showing "just now". | Low | `ctx.request_repaint_after(30 s)` while any host shows an age. |
| C5 | **Cache files of hosts removed by editing the file** (then Reload config) stay in the cache directory until "Clear cache". They are harmless and are never shown, because only configured hosts are loaded. | Low | On reload, remove the cache files of hosts that are gone (same as removing in the GUI). |
| C6 | `App::refresh` sets the status to "connecting…" even when the kept connection is reused; the worker then sends "refreshing…" (a brief flicker). | Cosmetic | Set "refreshing…" if the worker has a session for the host (`Worker::has_session`). |

No mismatch was found for:
- SPEC-012: parallel hosts, a busy host is not refreshed twice, no automatic refresh at start.
- SPEC-013: plain message plus detail.
- SPEC-014: file per host, cached marker, kept after a failure, clear.
- SPEC-015: tree, details, toolbar, settings, filter.
- SPEC-017: the GUI uses only the trait.
- SPEC-005: add/edit/remove are validated with `Config::validate` and saved; a failed save is reverted.

## 6. Other improvements suggested

1. **UUID from the XML:** if `dominfo` fails or lacks a UUID, take `<uuid>` from the domain XML. Both are always present on a real host, but the cache and odd hosts benefit.
2. **Optional refresh at start:** `[ui] refresh_on_start = true` in the config, for users with an agent or unencrypted keys (no prompts). The default stays off.
3. **Keyboard navigation** in the tree (up/down to move, Enter to refresh the host), for accessibility.
4. **Phase 5 (packaging)** next: release builds per OS as CI artifacts (zip/tar.gz), then a crosscheck and `v1.0.0`.
