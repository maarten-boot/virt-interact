## 2. Code checked against the Spec and Plan

| # | Finding | Severity | Proposed fix |
|---|---------|----------|--------------|
| C1 | **SPEC-001 broken for disabled widgets.** egui draws disabled widgets at `disabled_alpha = 0.5` (egui `style.rs`). Black text at 50% on white gives about 4:1, below 4.5. `theme.rs` does not set `disabled_alpha`, and `palette.disabled_text` is never used. There are no disabled widgets yet, but phase 4 adds them. | **High** (latent) | Set `disabled_alpha = 1.0` in `theme::visuals`. Show the disabled state by drawing disabled labels in `palette.disabled_text` (which meets the minimum) and by the absence of hover. |
| C2 | **The egui theme mapping has no test.** TC-003 tests the palette, but nothing checks that every colour pair egui actually uses (`Visuals`) comes from the palette and meets the minimum. C1 went unnoticed because of this. | Medium | Add a vi-gui unit test (new **TC-007**): for every contrast level, collect the text/stroke colours and the fill colours from the `Visuals`, check every pair ≥ min, and check `disabled_alpha == 1.0`. |
| C3 | `ContrastLevel::custom(+inf)` clamps to 4.5 with the message "below the minimum". Real TOML can contain `inf`. NaN → 4.5 is fine. | Low | Map `+inf` to 21 with the "above the maximum" message. Keep NaN → 4.5 with a message "not a number". Extend TC-004. |
| C4 | A `port = 0` in a host passes validation. | Low | Reject port 0 in `Config::validate` (TC-024, extended). |
| C5 | `Config::save` creating a missing parent directory (the first save on a fresh system) is not tested. | Low | Extend the TC-021 test: save into a non-existent subdirectory and check that the file exists. |

## 6. Other improvements suggested

1. **Push the repo**, or run CI locally with `act`, so TC-010 really runs on Windows and macOS. That's the biggest untested risk so far (GUI dependencies, paths).
2. **Install rustup**, so the local toolchain matches CI and eframe can move to 0.37 when wanted (see Plan).
3. **TC-006 automation:** an egui `kittest`-style harness, or a small test that drives `App::set_contrast` and checks the saved file, would replace the manual check. This needs `App` to be split out of `main.rs` into a `lib`-style module.
4. **Config hot reload:** SPEC-005 says "a host added in the file appears after a reload", but there is no reload action yet. Plan it explicitly in phase 4 (toolbar "Reload config").
5. **Error banner:** messages repeat the full config path. Consider showing only the file name, with the full path in a tooltip.
