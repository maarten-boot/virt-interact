## 3. Findings

| # | Finding | Proposed fix |
|---|---------|--------------|
| C1 | **Reopen race (code).** "Close console" (and forgetting a host) removes the console from the worker's table at once, but the old task needs up to 2 s more to stop the viewer. Reopening in that time starts a second task for the same key; when the old task ends it removes the key from the table unconditionally, which drops the **new** console's close handle, so the new console is closed right after it opens. Its `Closed` event also clears the app's state of the new console. | Keep the key in the worker's table until its task has ended: closing (or forgetting) only takes the close handle out. `open_console` refuses while the old task is still stopping; the app shows "closing…" (disabled, same place as "opening…") until the `Closed` event arrives. Add a worker test: close and reopen at once → the second open is refused until `Closed`, then works. |
| C2 | **SIGKILL goes to the viewer only (code vs Spec).** The Spec says closing sends SIGTERM to the viewer's process group, then SIGKILL after 2 s "so the helpers of a wrapper script stop too". After 2 s the code kills only the viewer process (`child.kill()`); a helper that ignores SIGTERM keeps running. | Send SIGKILL to the group too after the 2 s (`ViewerGroup::kill`), then kill the viewer as now. Extend `close_console_stops_the_viewer` with a helper that ignores SIGTERM. |
| C3 | **App exit (Spec wording).** The Spec says the same happens when the app is closed; on exit there is no 2 s wait: the group gets SIGTERM and the viewer SIGKILL at once (task dropped). | Spec: "When the app is closed, the viewer's group gets SIGTERM and the viewer is killed at once." |
| D1 | **TC-102 is stale.** It is still "planned" (tunnel to the test VM's VNC port, an example in 6.2). The RFB handshake through the tunnel is now covered by TC-106 (Linux, real TigerVNC, local runner) and TC-102a (SSH channels); a real VM over SSH is TC-103c. | Mark TC-102 "covered by TC-102a + TC-106; real VM over SSH: TC-103c". |
| D2 | **Reconnect not in the Spec.** When the kept connection has broken, the console reconnects once (`connection_lost`), like a refresh (SPEC-006). SPEC-018 does not say so. | Add to SPEC-018: "If the kept connection has broken, the app reconnects once." |
| D3 | TC-105 names the extra directories "Homebrew"; MacPorts `/opt/local/bin` is also searched (tested in TC-112). | TC-105: "Homebrew, MacPorts (TC-112)". |
| D4 | `windows_dirs` uses `dedup()`, which only drops neighbouring doubles; `ProgramFiles` and `ProgramW6432` are usually the same folder and are not neighbours, so it is searched twice (harmless). | Drop doubles with a seen-set, keeping the order. |

## Resolution

All applied on 2026-11-17 after the user's OK:
- C1: the worker keeps a console's key until its task has ended (closing or forgetting only takes the close handle); `open_console` refuses meanwhile; the app shows "closing…" (`ConsoleState::Closing`). Test `reopen_waits_until_the_old_viewer_stopped`; it fails with the old `close_console`.
- C2: after 2 s the group gets SIGKILL (viewer still running), or, when the viewer stopped but helpers remain, the group gets SIGKILL after 2 s more. `close_console_stops_the_viewer` now uses a wrapper and helper that ignore SIGTERM (both paths); it fails without the SIGKILL.
- C3, D2: SPEC-018 updated. D1: TC-102 marked covered. D3: TC-105 wording. D4: each `VirtViewer*\bin` folder searched once.
