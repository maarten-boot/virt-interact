## 2. Code checked against the Spec and Plan

| # | Finding | Severity | Proposed fix |
|---|---------|----------|--------------|
| H1 | **Hover changes the layout (user report).** In egui 0.35 a framed widget's size is its content plus inner margin plus **twice its border width**. Our theme (crosscheck 01) draws borders 1.0 px wide at rest, 1.5 px on hover and 2.0 px when pressed. So any hovered or pressed button or label grows by 1–2 px: its neighbours shift, and if it is the widest row in the tree, the left panel widens and the separator and the whole right panel move. That goes against the user's rule: feedback must not cause movement anywhere else. | **High** (user-visible, distracting) | (a) The same border width (1.0) in every widget state; hover and press differ only in colour: a text-coloured border and the hover background. The box stays visible; nothing grows. (b) A test that every widget state has the same border width and `expansion = 0`. (c) A headless test that moves the pointer across the tree and checks that the panel width stays the same. Add a Spec line: "Hover, press and selection feedback never changes size or position of anything." |
| H2 | **The tree panel's width follows its content.** Inside a vertical-only scroll area, the widest row sets the panel width. A status text that changes width ("connecting…" → "refreshing…" → "ok, just now") or a longer VM name after a refresh also moves the separator, even without hovering. | Medium (same symptom as H1) | Put the tree in a scroll area that also scrolls horizontally and does not shrink (`ScrollArea::both().auto_shrink([false, false])`). The panel width then changes only when the user drags the separator; wide rows scroll. The headless test from H1(c) also covers a status change. |
| C1 | **macOS: `virsh` from Homebrew is not found when the app is started from Finder or the Dock.** GUI apps started by launchd get `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, but Homebrew installs `virsh` in `/opt/homebrew/bin` (Apple Silicon) or `/usr/local/bin`. In `"auto"` mode the local entries are then missing, and in `"always"` mode the shell cannot find `virsh`. This is expected from how launchd works; it was not tested on a Mac. | Medium (macOS) | Search `PATH` plus a short list of well-known directories (`/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `/bin`). Give the `LocalRunner` that same search path, so detection and execution always agree. Settings already shows where `virsh` was found. Test: `find_virsh_in` with the extra directories, and a runner that uses the resulting path. |
| C2 | **The local entry's label ignores its URI.** `display_name` says "localhost (system)" for `@local-system` whatever `[local] libvirt_uri` is, so `libvirt_uri = "qemu:///session"` (one entry) is shown as "(system)", and a custom URI such as `lxc:///` also shows as "(system)". | Low | Derive the label from the URI: `qemu:///system` → "localhost (system)", `qemu:///session` → "localhost (session)", anything else → "localhost (<uri>)". Extend TC-110. |
| C3 | When the local entries disappear (`enabled = "never"`, or `virsh` removed), their cache files stay until "Clear cache". Same class as crosscheck 01 C5; harmless, never shown. | Low | Remove the cache file of an entry that disappears in `sync_hosts`, for local entries and for removed hosts alike (`sync_hosts` already knows which entries go). |
