## 3. Findings

| # | Finding | Proposed fix |
|---|---------|--------------|
| C1 | SPEC-021 says "the refresh timeout (SPEC-012) applies to the whole read". The code applies `[ssh] command_timeout_secs` to each API request (each page of up to 500 objects), like the command timeout of SPEC-012 for each virsh command. | Spec: "the command timeout applies to each request (each page)". (A whole-read limit would cut off large vCenters.) |
| C2 | SPEC-021 says CD-ROM "(ISO path or empty)"; the code also shows a host or client device ("host device", "client device"), and a raw device mapping disk as a block device. | Spec: list these cases. |
| D1 | SPEC-023 says `known_certs` is in "the app's config directory"; the code keeps it next to the config file in use, so with `--config` it is beside that file. | Spec: "next to the config file (also with `--config`)". |
| D2 | SPEC-023 does not say what happens when `known_certs` cannot be written after the user accepts: the code stops the connection with an error naming the file (SPEC-008 accepts an SSH host key for that connection only, with a warning). | Keep the code (no silent trust without a pin); Spec: say so. |
| T1 | The rule "an expired session (`NotAuthenticated`) or a lost vSphere connection logs in again once" (`worker::connection_lost`) has no test. | Unit test: `NotAuthenticated`, `Connect` and `Http` count as lost; `InvalidLogin`/other faults, certificate errors and SSH-unrelated errors do not. |
| T2 | TC-135 (password wiped, never in a log line, the cache or the config) is still "planned": wiping is in the code (`Secret`, `Request`, `WipedBuf`) and `Debug` hides it (TC-130), but there is no test that the logs and the saved files do not contain it. | Test against vcsim with a distinctive password: capture all log output of connect + inventory + logout and check the password is absent; check the saved config and cache files too. |

No other mismatches between Spec, Plan and code.
